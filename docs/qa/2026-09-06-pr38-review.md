### 1. `users.depositTotal` 비정규화 (N-1) — 통과

- **읽기→쓰기 순서**: `api/deposit/route.ts:45-49`의 `sumDepositsInTx`는 `tx.get(query)` 하나뿐이고, 첫 `tx.update/set`(`:52-62`)보다 **앞**. Firestore "모든 읽기 → 모든 쓰기" 제약 준수. `increment` 대신 읽은 값 기반 산술이라 이 순서가 필수인데 지켜졌다.
- **동시 입금 2건 중복 없음**: 두 트랜잭션 모두 `userRef`를 `tx.get`(`:43`) → 낙관적 잠금. 먼저 커밋한 쪽이 `depositTotal`을 쓰면 나중 쪽은 ABORTED → 재시도 시 `prevDepositTotal`이 이미 숫자라 스캔 없이 `+amount`. **이중 합산 불가.** (필드가 없는 상태에서 둘 다 스캔해도 커밋은 하나만 성공.) 단, 쿼리 결과를 트랜잭션에 넣는 것이 문서 잠금까지 보장하진 않으므로 안전판은 `userRef` 읽기 — 그게 있어서 성립.
- **첫 입금 타임아웃**: 스캔 범위가 `consumerId == uid && type == deposit`으로 **회원 1명분**. 개인 입금 거래는 현실적으로 수백 건 이하 → 문제 없음. 최악(1만 건)이어도 단일 인덱스 쿼리 수백 ms. 전역 스캔이던 이전판 대비 3~4자릿수 개선. 트랜잭션 60초 한도 대비 여유.
