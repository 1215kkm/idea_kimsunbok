# CMS + ASP 사업 모델 요건 분석 및 문제점

## 1. 개요

다랜드(Dataland)가 **CMS(Cash Management Service, 자동이체)** 와 **ASP(Application Service Provider, 소프트웨어 임대)** 모델을 결합하여 사업을 구축하려는 요건에 대한 분석 문서입니다.

### 사업 모델 요약
- **ASP**: 기업에게 다랜드 플랫폼(소비 데이터 관리, 리워드 시스템 등)을 월 사용료 방식으로 임대
- **CMS**: 매월 ASP 서비스 사용료를 은행 자동이체로 수금
- **비선형 연계**: ASP 사용료(1%)도 다랜드 비선형 공식에 의해 120% 증액 적립되어 비용 부담 상쇄
- **핵심 조건**: 소비자가 지출하는 비용만 CMS로 청구하고, 다랜드 내부 멤버십 비선형시스템 운영은 CMS 매출로 잡지 않을 것

### 의뢰자 보충 설명 (2차 피드백)

위 사업 모델에 대한 문제점 분석 후, 의뢰자가 아래 핵심 보충 정보를 제공하였습니다.

1. **효성CMS 파트너십**: 다랜드는 자체 CMS를 구축하지 않고, **효성CMS의 파트너 회사**로 가입합니다. 효성CMS는 금융, 제조, 비영리, 종교법인 등 **450만개 파트너사**를 보유한 국내 최대 CMS 서비스로, 금융허브 기능은 모두 효성CMS에서 처리합니다.
2. **서비스 매출 1% → 효성CMS**: 파트너 회사들이 서비스 매출의 1%를 효성CMS에 제공하는 구조입니다.
3. **다랜드의 역할 한정**: 다랜드는 소비자의 지출금액을 충전된 데이터에서 차감하여 비선형 공식으로 **120% 증액 적립하는 역할만 수행**합니다. 그 외 판매자 & 소비자가 자체적으로 적립금액을 집행합니다.
4. **판매자 = 또 다른 소비자**: 쇼핑몰, 제조업체, 비영리법인 모두 판매자이자 소비자입니다. 일반 쇼핑몰 & 회원제 운영 시스템보다 더 간단히 운영 가능합니다.
5. **특허 출원 완료**: 비선형 공식은 **피타고라스 공식에 근거한 수학적 산식**으로 특허 출원이 완료되었습니다. 특허청 심사관들(BM특허 다수 심사 경험)이 검증하였으며, 사회 통념상 맞지 않으면 출원 자체가 불가합니다.
6. **글로벌 확장 비전**: 국내외 IP에서 신용(현금)카드를 사용하는 전 세계인이 다랜드 클라이언트가 될 수 있습니다.

> **의뢰자 핵심 요청**: "이점의 논리로 제작해 주시기를 바랍니다" — 위 장점들을 시스템에 반영할 것

## 2. 식별된 문제점 (7가지)

### 문제점 1: 매출 오분류 위험
CMS가 소비자의 거래 전체 금액(예: 10,000원)을 매출로 잡게 되면, 비선형 시스템이 120%(12,000P)를 지급하는 구조와 불일치가 발생합니다.

- CMS 수금액: 10,000원 (실제 돈)
- 비선형 적립액: 12,000P (내부 포인트)
- **차이 2,000P의 출처와 회계 처리가 불명확**

CMS로 잡히는 금액은 ASP 서비스 이용료(예: 거래액의 1%)만이어야 하며, 거래 전체 금액이 아닙니다.

### 문제점 2: 세무 감사 노출
비선형 내부 연산(a→f 분배 체인, 이탈모드, 보정모드 등)이 CMS 기록에 포함되면 세무 당국이 이를 **과세 대상 매출**로 분류할 수 있습니다.

- 비선형 분배 체인의 `f` 값(12% 수수료)이 CMS 매출로 잡히면 실제 수금하지 않은 금액에 세금 부과 가능
- 내부 포인트 적립/분배는 **매출 이벤트가 아닌 내부 장부 기입**이므로 CMS와 분리 필수

### 문제점 3: CMS 제공업체 규정 준수
~~실제 CMS 자동이체를 운영하려면 **금융결제원** 또는 **효성CMS** 등과 계약해야 합니다.~~

> **[2차 피드백 반영]** 다랜드는 **효성CMS 파트너 회사**로 가입 예정이므로, CMS 인프라 계약 문제는 해소됩니다. 효성CMS는 450만개 파트너사를 보유한 검증된 CMS 서비스입니다.

- ~~CMS 제공업체는 자동이체 사유를 엄격히 제한함~~ → 효성CMS 파트너 가입으로 해소
- 유효한 CMS 출금 사유: "ASP 월 서비스이용료", "플랫폼 구독료" 등 — **효성CMS 파트너 계약 범위 내에서 사용 가능**
- **비선형 리워드 계산, 멤버십 풀 운영 등은 여전히 CMS 출금 사유로 사용 불가** (분리 원칙 유지)
- 효성CMS 파트너 심사 시 비선형 시스템에 대한 설명이 필요할 수 있으나, **CMS 청구 대상은 ASP 서비스 이용료만**이므로 심사 통과 가능성 높음

### 문제점 4: 지적재산(노하우) 유출 위험
CMS 기록에 비선형 분배 체인 데이터(a→f 값, 멤버십 풀 크기, 보정 모드 값 등)가 포함되면:

- CMS 제공업체 또는 제3자가 기록을 열람할 경우 **비선형 공식 역설계 가능**
- 현재 코드에서 `transactions` 컬렉션에 `nonlinearResult`(principal, bonus, totalAccumulation, rate, memberCount, perMemberAmount, advertiserReward)가 직접 저장되고 있음
- **의뢰자가 명시한 "다랜드 노하우 기술로서 CMS 매출로 하면 아니 된다"는 조건에 위배**

### 문제점 5: ASP 수수료 순환 참조
요건에 따르면 "ASP 사용료 1%를 지불하면 다랜드의 지출로서 120% 증액 적립"됩니다.

이 구조의 문제:
- CMS로 1% 수금 → 비선형 시스템이 1.2% 환급 → **CMS 수금액보다 더 많은 포인트 발생**
- 이 0.2% 차이의 재원은 비선형 시스템 내부에서 충당되어야 함
- 수학적으로는 비선형 모델 내에서 유효하나, **외부 회계/감사 관점에서는 설명이 어려움**
- CMS 수금(실제 돈)과 비선형 적립(내부 포인트)의 단위가 다르므로, 1:1 환산 시점에서 자금 흐름 설명 필요

### 문제점 6: 이중 원장 정합성
CMS/비선형 분리 시 두 개의 원장을 운영해야 합니다:

| 원장 | 내용 | 단위 |
|------|------|------|
| CMS 원장 | 실제 은행 자동이체 기록 | 원(KRW) |
| 비선형 원장 | 내부 포인트 적립/분배 기록 | 포인트(P) |

- 두 원장 간 **정합성 검증 로직**이 필요
- CMS 원장의 합계와 비선형 원장의 특정 값(예: ASP 수수료 부분)이 일치해야 함
- 현재 코드는 단일 `transactions` 컬렉션으로 모든 것을 처리하여 분리 불가 상태

### 문제점 7: 소비자 혼동
현재 CMS 등록 화면(`cms-register/page.tsx`)에서:

- 비선형 시스템 계좌 ID(`NL-{uid}`)가 CMS 등록 과정에 직접 노출됨 (Step 1)
- 완료 화면에서 "적립 방식: 120% 증액 적립"이 CMS 가입 확인과 같은 카드에 표시됨
- 소비자가 **CMS 자동이체로 120%가 빠져나간다고 오해**할 수 있음
- CMS는 서비스 이용료만 수금하고, 120% 적립은 별도 내부 시스템임을 명확히 분리해야 함

## 3. 현실적 규제/절차 이슈

### 3.1 전자금융거래법
- CMS 자동이체 사업을 운영하려면 **전자금융업 등록** 또는 **CMS 대행 업체 계약** 필요
- 금융결제원 CMS 이용 시 가맹점 등록 절차 필요 (사업자등록증, 서비스 내용 심사 등)
- 자체적으로 CMS를 운영하는 것이 아닌 **CMS 대행사(효성, KSNET 등)를 통한 간접 이용**이 현실적

### 3.2 유사수신행위 규제 (가장 중대한 리스크)
- **유사수신행위의 규제에 관한 법률**: "장래에 투자금의 전액 또는 이를 초과하는 금액을 지급하겠다는 것을 암시하여 불특정 다수인으로부터 자금을 조달하는 행위"를 금지
- "지출할수록 120% 증액 적립"은 **원금 이상의 수익 약속**으로 해석될 여지가 있음
- 비선형 공식이 수학적으로 유효하더라도, 마케팅 표현과 법적 해석은 별개

> **[2차 피드백 반영]** 의뢰자에 따르면, 비선형 공식은 **피타고라스 공식에 근거한 수학적 산식으로 특허 출원이 완료**되었습니다. 특허청 심사관들(BM특허 다수 심사 경험)이 검증하였으며, 사회 통념상 맞지 않으면 출원 자체가 불가합니다. 이는 비선형 공식의 **기술적 정당성**을 뒷받침하는 근거가 됩니다.
>
> **단, 특허 출원 ≠ 법적 면제**: 특허 출원은 기술의 신규성과 진보성을 인정받은 것이지, 금융규제법으로부터의 면제를 의미하지 않습니다. 유사수신행위 규제는 기술의 유효성이 아닌 **자금 조달 방식과 수익 약속의 형태**를 기준으로 판단합니다.

- **반드시 법률 전문가(금융규제 전문 변호사)의 사전 검토 필요** — 특허 출원 사실을 법률 검토 시 유리한 근거로 활용 가능

### 3.3 통신판매업/PG 관련
- ASP 서비스 제공자로서 **통신판매업 신고** 필요
- 타인의 자금을 수금/관리하는 경우 **PG(결제대행) 라이선스** 또는 PG사 제휴 필요
- CMS로 수금한 자금의 에스크로(예치) 의무 검토 필요

### 3.4 개인정보보호
- CMS 등록 시 은행 계좌 정보 수집 → **개인정보보호법** 준수 필요
- 계좌 정보 암호화 저장, 동의 절차, 파기 정책 수립 필요

## 4. 권고사항

### 즉시 조치 (Before Launch)
1. **법률 검토**: 120% 적립 구조가 유사수신행위에 해당하는지 금융규제 전문 변호사 검토
2. **CMS 대행사 계약**: 효성CMS, KSNET 등 CMS 대행사와 사전 협의 및 계약
3. **사업자 등록**: 통신판매업 신고, 전자금융업 등록 여부 확인

### 시스템 설계 (Technical)
1. **데이터 분리**: CMS 청구 기록과 비선형 시스템 기록을 별도 데이터베이스/컬렉션으로 분리
2. **CMS 기록에 비선형 데이터 미포함**: CMS 관련 기록에는 ASP 서비스 이용료, 결제수단, 청구 일자만 저장
3. **비선형 시스템 접근 제한**: 비선형 분배 체인 데이터는 내부 전용으로, 외부 시스템(CMS, 세무 보고 등)에 노출하지 않음
4. **원장 정합성 검증**: CMS 원장과 비선형 원장의 자동 대사(reconciliation) 로직 구현

### UI/UX 개선
1. **CMS 등록 화면에서 비선형 계좌 ID 제거**: CMS는 서비스 이용료 수금만 담당
2. **120% 적립 안내 분리**: CMS 가입 완료와 비선형 리워드는 별도 섹션으로 시각 분리
3. **ASP 서비스 약관 명시**: 1% 서비스 이용료가 무엇에 대한 대가인지 명확히 고지

## 5. 결론

CMS + ASP 모델 자체는 기술적으로 구현 가능하며, 의뢰자의 2차 피드백을 통해 몇 가지 핵심 이슈가 해소 또는 완화되었습니다:

### 해소/완화된 이슈
- **CMS 인프라 문제 (문제점 3)**: 효성CMS 파트너 가입으로 CMS 제공업체 계약 문제 해소. 450만 파트너사를 보유한 검증된 플랫폼 활용.
- **기술적 정당성 (문제점 5 관련)**: 비선형 공식의 특허 출원 완료(피타고라스 공식 기반)로 수학적 유효성 입증. 특허청 심사관 검증 완료.
- **사업 확장성**: 글로벌 확장 가능성 — 국내외 IP에서 신용(현금)카드를 사용하는 전 세계인이 클라이언트 대상.
- **운영 간소화**: 판매자 = 소비자 구조로, 일반 쇼핑몰/회원제보다 간단한 운영 가능.
- **역할 명확화**: 다랜드는 지출금액 차감 → 120% 증액 적립 역할만 수행. 금융허브 기능은 효성CMS 담당.

### 여전히 필요한 조치
- **유사수신행위 규제 검토**: 특허 출원이 기술적 정당성을 뒷받침하나, 금융규제법으로부터의 면제를 의미하지 않음. **법률 전문가 사전 검토 여전히 필수.**
- **매출 오분류 방지 (문제점 1, 2)**: CMS 청구 영역과 비선형 리워드 영역의 **완전한 분리** 원칙 유지.
- **이중 원장 정합성 (문제점 6)**: CMS 원장(효성CMS)과 비선형 원장(다랜드 내부)의 대사 로직 필요.
- **지적재산 보호 (문제점 4)**: 비선형 분배 체인 데이터의 외부 시스템 노출 방지.

시스템 설계 시 CMS 청구 영역(효성CMS 처리)과 비선형 리워드 영역(다랜드 내부)의 **완전한 분리**가 핵심 원칙이 되어야 합니다.

## 6. 의뢰자 3차 피드백 반영 (2026-04-21)

의뢰자로부터 이메일 및 이미지 자료를 통해 추가 요건이 전달되었습니다.

### 6.1 회원 탈퇴 환불 로직 (신규 구현)

- 엔진 함수: `calculateInviteReward(baseAmount)` — `nonlinear-engine.ts`에 추가

## 7. 의뢰자 4차 피드백 반영 — 총량유지 모드 (2026-05-02)

의뢰자가 4장의 이미지 자료로 **"데이터 총량 유지하는 방법"** 핵심 메커니즘을 추가 전달하였습니다.

### 7.1 락(고리) 메커니즘 — 출금에도 비선형공식 적용 (구현 완료)

**의뢰자 핵심 문구**: "지출 전에 락(고리)을 걸어놓고 → 지출금액만큼 비선형공식에 분배 → 120%(=20%×5) 확보 → 100%만 본인 오프계좌로 이체"

| 항목 | 변경 전 | 변경 후 |
|------|------|------|
| 출금 흐름 | 100,000P 단순 차감 → 100,000원 이체 | 비선형공식 → 120,000P 확보 → **100,000원 이체 + 20,000P 시스템 수익** |
| 시스템 총량 | 감소 | **유지** (락-고리 메커니즘) |

`withdraw/page.tsx`의 confirm/complete 단계에 비선형공식 분배 결과를 표시하도록 추가. 회원 탈퇴 환불 함수(`calculateWithdrawalRefund`)를 일반 출금에도 재사용.

### 7.2 초대 리워드 금액 가변화 (구현 완료)

의뢰자 예시는 **100백만원 = 1억원**(1P=1원) 단위. 사업자 데모용으로 4가지 프리셋 + 직접 입력 추가:

- 10만P (일반 회원 초대)
- 100만P (VIP 초대)
- 1천만P (프리미엄 초대)
- 1억P (사업자 데모용)
- 직접 입력 (1만 ~ 10억P)

초대 링크에 `?invite=CODE&amt=N` 형식으로 금액 포함.

### 7.3 총량유지 모드 페이지 신규 (`/quantity-mode`) (구현 완료)

5단계 흐름 시각화 페이지 신설:

1. **이체** — 회원이 본인 오프계좌로 충전금액 이체 (비선형공식 120% 확보)
2. **분배** — 광고주가 신규 가입회원에게 분배 (광고주 충전금액에서 차감)
3. **신용카드 결제** — 영수증으로 다랜드 비선형시스템 충전금액에서 차감 (은행 직행 X)
4. **비선형공식 분배** — 차감 금액을 분배 알고리즘에 투입
5. **다랜드 계좌 재충전** — 12,000,000을 다랜드 소비자 계좌에 재충전 → 총량 유지

**중앙관리서버 처리 능력**: 초당 30만 건 — 비선형공식 무한 반복으로 기술적 적정성 확보.

### 7.4 데이터노동(Data Labor) 용어 통일 (구현 완료)

의뢰자 명시 용어: "지출(분배)하여도 항상 120% 가능하므로 지속할 수 있다 — 이것을 **데이터노동**이라 합시다."

### 7.5 적립 → 재충전 표현 보강 (핵심 위치)
