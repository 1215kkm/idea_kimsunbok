다랜드 — 실제 운영을 위한 작업 가이드

비선형공식 120% 리워드 플랫폼 · 현 상태 진단과 남은 과제 · 2026.04

한 줄 요약 — 지금 만들어진 건 "기능 미리보기용 프로토타입"입니다. 실제 돈이 오가는 운영을 하려면 기술(배포/보안/자동화)과 사업(법·제휴·자금관리) 두 축의 작업이 필요합니다.

1. 지금 프로그램은 어떻게 돌아가나요?

현재 모드 — 베타 체험 모드 (Demo)

  • 사용자 데이터가 각자의 브라우저 안(localStorage)에만 저장됩니다.
  • 다른 기기에서 로그인하면 내역이 보이지 않습니다. (같은 브라우저 = 같은 계정)
  • 포인트 출금은 실제 은행 이체가 아닌 가짜(시뮬레이션)입니다.
  • 회원가입도 "이메일을 이 브라우저에 기록"하는 수준 — 비밀번호가 서버에서 검증되지 않습니다.

→ 테스터가 UX를 체험하고 피드백 주기에는 충분하지만, 실제 운영은 불가능합니다.

2. 실제 운영 시 사용자 흐름

소비자(일반 회원) 관점

1
앱/웹 가입 · 본인인증(KYC)
2
본인 은행계좌 등록
3
신용카드로 평소처럼 결제
4
영수증 자동 인식 → 등록
5
120% 포인트 적립 (비선형공식)
6
포인트를 은행계좌로 출금

광고주 관점

  1. 광고주 계약 체결 → 다랜드에 회원으로 가입
  2. 본인이 가입시킨 회원들의 지출 5%가 광고주 계좌에 지속 적립
  3. 정산 주기(주/월)에 실제 입금

운영자(다랜드 본사) 관점

  1. 회원 가입·본인인증 승인
  2. 거래 데이터 검증 (영수증 실재성·중복·부정 탐지)
  3. 비선형공식에 따라 포인트 자동 분배 (Cloud Function)
  4. 효성CMS와 연동해 회원 충전금 정산
  5. 출금 요청 승인 → 은행 펌뱅킹으로 실제 이체
  6. 매일/매월 회계 정산, 특허/세무/고객지원 대응

3. 제작자(개발자)의 남은 할 일

제작자 = 코드를 작성하고 시스템을 구축하는 사람 (현재 당신)

Phase 1 — 즉시(이번 주) : 배포와 실 DB 연결

#작업우선순위예상 난이도
1Vercel 배포 URL 확인 → 테스터에게 공유높음낮음
2Firebase 프로젝트 생성 + Auth/Firestore 활성화높음낮음
3.env.local에 Firebase 키 주입 + Vercel 환경변수 등록높음낮음
4firestore.rules 배포 (firebase deploy --only firestore:rules)높음낮음
5FeedbackButton 이메일 주소 실운영 주소로 교체중간낮음

Phase 2 — 단기(1~3주) : 핵심 기능 실연동

#작업우선순위설명
6API Routes 구축
(/api/transactions, /api/withdraw)		높음서버 측 검증·로깅
7Cloud Functions: 지출 → 비선형 분배 자동화높음포인트 지급 신뢰성
8관리자 패널: 실제 출금 승인 플로우높음운영팀이 사용할 화면
9영수증 OCR 통합 (Google Vision / CLOVA OCR)중간수동 입력 → 자동 추출
10본인인증(KYC) 연동 — PASS·NICE·KCB높음전자금융법 요구사항
11은행 펌뱅킹/오픈뱅킹 API 연동 (실제 출금 실행)높음운영자가 발급받은 API키 사용

Phase 3 — 중기(1~3개월) : 안정·보안·확장

  • 부정거래 탐지: 영수증 중복·금액 이상 탐지 규칙
  • 자동화된 회계 리포트 (일/월 단위 지출·적립·출금 총액)
  • 에러 모니터링 (Sentry), 성능 모니터링 (Vercel Analytics)
  • PWA / 모바일 앱 빌드 (사용자 설치)
  • 시뮬레이션 페이지 정상화 (현재 iframe 깨짐)
  • CI/CD 테스트 강화 — 현재 auto-review-and-merge 외 E2E 테스트 추가
  • DB 백업 · 재해 복구 시나리오

4. 운영자(사업·법률·재무)의 남은 할 일

운영자 = 사업을 실제로 돌리는 사람 (법인 대표·기획자·재무담당)

A. 법·제도 준비 (필수)

⚠️ 주의 — 포인트를 현금으로 출금해주는 순간 "선불전자지급수단 발행업"으로 분류될 가능성이 매우 큽니다. 등록 없이 서비스를 열면 전자금융거래법 위반이 됩니다.
#작업담당기관
1법인 설립 + 사업자등록 (아직이면)세무서
2전자금융업 등록 (선불전자지급수단 발행)금융위원회 / 금감원
3개인정보처리방침 · 이용약관 · 환불정책 작성/공시법률자문
4통신판매업 신고 (광고주 수수료 수취 모델이면)관할 구청
5특허 출원 완료 확인 + 상표 등록특허청 / 변리사
6정보보호 인증 (ISMS-P) — 중장기KISA

B. 파트너십·계약

  • 효성CMS 공식 파트너십 계약 — 자동이체·대행수납 연동
  • 은행 법인계좌 + 펌뱅킹 계약 (출금 실행용)
  • 본인인증 기관 (PASS/KCB/NICE) 위탁 계약
  • OCR 제공사 계약 (CLOVA, Google Vision 등)
  • 광고주 모집 — 표준 계약서, 정산 주기, 수수료율 확정
  • 가맹점 / 결제 파트너 (장기) — 직접 가맹 모델 or 기존 카드사 데이터 활용 모델

C. 자금·회계

자금 흐름 핵심 — 회원의 지출 원금은 효성CMS를 통해 다랜드 계좌에 수납되고, 비선형공식 120% 중 "초과 20%는 광고주 수수료 + 회원 충성도 재투자"에서 충당됩니다. 자금 불일치 시 즉시 지급불능(파산) 리스크이므로, 회계·준비금 관리가 기술보다 더 중요합니다.
  1. 초기 운영자금 확보 (회원수 N명 × 평균 출금금액 × 여유분)
  2. 회원 충전금(예수금) 별도 계좌 보관 — 전자금융법상 분리보관 의무
  3. 세무사/회계사 월간 정산 계약
  4. 매일의 입금-출금-적립 내역 대조
  5. 광고주 정산 시스템 (월 마감)

D. 운영팀·고객지원

  • 운영자 역할 분담: 출금 승인자 / 부정거래 감시자 / 고객상담
  • 고객센터 채널 (카카오톡 채널, 이메일, 1:1 문의)
  • 운영 매뉴얼 작성 — 출금 승인 기준, 부정거래 대응 절차, 환불 기준
  • 약관 위반·부정 계정 처리 워크플로우

E. 마케팅·성장

  • 베타 테스터 모집 (지인 20~50명 → 피드백 반영)
  • 1차 정식 오픈 전 보도자료 · 랜딩페이지 준비
  • 광고주 확보 영업 자료 (사업 소개서, 수익 시뮬레이션)
